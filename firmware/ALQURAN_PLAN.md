# Al-Quran Firmware & PWA Architecture Plan (`ALQURAN_PLAN.md`)

## 1. Scope & Architectural Constraints

1. **Opt-In Firmware Build**:
   - The standard `waveshare_154` target (`bacain_waveshare_154_factory.bin`) compiles with `CONFIG_BOARD_ALQURAN_ENABLE=n`. Zero Quran code, state arrays, or UI strings are included in the default binary ([firmware/RULES.md](./RULES.md) §2.3).
   - A dedicated build profile `waveshare_154_alquran` sets `CONFIG_BOARD_ALQURAN_ENABLE=y` and outputs `bacain_waveshare_154_alquran_factory.bin`.
2. **Asymmetric Complexity Partitioning**:
   - The Web Companion PWA (`web/`) performs font loading, Arabic contextual shaping, SVG/QCF glyph rasterization, 1-bit bounding-box cropping, and ASCII line wrapping for `latin`, `translate`, and `tafsir` layers.
   - The ESP32-S3 receives a normalized binary package (`quran.bqm`) and executes zero-allocation 1-bit bitmap blitting and fixed-offset reads within the `< 300 ms` wake-to-sleep budget.
3. **Independent Reading State**:
   - Standard book reading state (`reading_state_t` in `firmware/components/reader_core/book_library.h:49-55`) and `VIEW_MENU` index `0` (`Continue Reading`) remain exclusively tied to books.
   - Al-Quran state (`quran_state_t`) is persisted independently in NVS namespace `"quran"` and `RTC_DATA_ATTR`, accessed through its own top-level `Al-Quran` menu entry.
4. **Hardware Interlock, Display Geometry & Lazy Module Loading on PWA**:
   - `BLE_SYNC_OP_GET_CONFIG` (`0x19`) in `firmware/components/ble_sync/ble_sync.c:1033-1075` is extended with `resp[10]` (`capabilities`, bit `0` = `CAP_ALQURAN_SUPPORT`), `resp[11..12]` (`BOARD_DISPLAY_WIDTH` `uint16_le`), and `resp[13..14]` (`BOARD_DISPLAY_HEIGHT` `uint16_le`).
   - The PWA does not include or preload Al-Quran scripts, fonts, or datasets in `web/index.html` by default. When `resp[10] & 0x01` is true, `web/app.js` dynamically imports `./components/quran-builder.js`, passes the device's exact display dimensions (`displayWidth`, `displayHeight`, `rotation`), and mounts `<quran-builder>` into `#mainContent`.

## 2. Answering #2: Mushaf Screen Packing vs. Single-Ayah Atomic View

On small 1-bit monochrome e-paper displays (`BOARD_DISPLAY_WIDTH x BOARD_DISPLAY_HEIGHT`, e.g., `200x200` on `waveshare_154` with a `W x (H - 32) px` usable body between the `16 px` header and `16 px` footer), **Ayah-Anchored Atomic View (1 Ayah per screen, paginated into subpages `1/N` when an ayah exceeds the viewport height)** is the recommended layout over continuous multi-ayah packing:

1. **Deterministic 2-Button Layer Cycling (`2x ▲`)**:
   - With only 2 physical buttons (`BOARD_BTN_UP_PIN=0`, `BOARD_BTN_DOWN_PIN=18`), there is no cursor to select which ayah on a multi-ayah screen should open when cycling `MUSHAF -> LATIN -> TRANSLATE -> TAFSIR -> MUSHAF`.
   - Locking each screen to a single `(surah, ayah)` ensures `2x ▲` always inspects the exact ayah currently displayed.
2. **Legibility on 1-Bit Monochrome**:
   - At `38 px` vertical line height, each word sprite retains `2 px` rasm strokes and distinct `2x2 px` harakat dots (`fatha`, `kasra`, `damma`, `shadda`, `sukun`, `madd`) without merging into adjacent lines.
   - Short ayahs that take fewer lines than the screen height are vertically centered in the `(BOARD_DISPLAY_HEIGHT - 32) px` viewport, improving visual separation around Uthmani diacritics and the ayah rosette (`۝`).
3. **Subpage Handling for Long Ayahs**:
   - When an ayah in `MUSHAF`, `LATIN`, `TRANSLATE`, or `TAFSIR` exceeds 1 screen (for example, Al-Baqarah 2:282), the PWA pre-splits the layer into `subpage_count` screens sized to the connected board's `displayWidth x (displayHeight - 32)` body area.
   - Single-clicking `▼` (`BTN_ID_PWR`) advances `subpage` from `0` to `subpage_count - 1`, then advances to `ayah + 1` (`subpage = 0`).

## 3. `.bqm` (BacaIn Quran Mushaf) Binary Container Specification

Generated by the PWA for the connected board's target display resolution (`display_width x display_height`) and stored at `/sdcard/books/quran.bqm` or `/spiflash/books/quran.bqm` (excluded from the regular `.txt` book list in `book_library_scan()`). All multi-byte integers are little-endian.

### 3.1 File Header (64 Bytes, Offset `0x0000`)

| Offset | Type | Field | Description |
| :--- | :--- | :--- | :--- |
| `0x00` | `char[4]` | `magic` | `"BQM1"` (`0x42, 0x51, 0x4D, 0x31`) |
| `0x04` | `uint16_t` | `version` | `1` |
| `0x06` | `uint8_t` | `layer_mask` | Bitmask: `bit0`=Mushaf, `bit1`=Latin, `bit2`=Translate, `bit3`=Tafsir |
| `0x07` | `uint8_t` | `mushaf_style_id` | `0`=Madinah Uthmani Hafs (KFGQPC), `1`=IndoPak 15-Line Naskh |
| `0x08` | `uint16_t` | `display_width` | Target board width in px (`BOARD_DISPLAY_WIDTH`, `64..1024`) |
| `0x0A` | `uint16_t` | `display_height` | Target board height in px (`BOARD_DISPLAY_HEIGHT`, `64..1024`) |
| `0x0C` | `uint16_t` | `total_surahs` | `114` |
| `0x0E` | `uint16_t` | `total_ayahs` | `6236` |
| `0x10` | `uint32_t` | `word_dict_count` | Number of unique 1-bit word sprites (`~18900`) |
| `0x14` | `uint32_t` | `surah_table_off` | Byte offset to `bqm_surah_entry_t[114]` |
| `0x18` | `uint32_t` | `ayah_table_off` | Byte offset to `bqm_ayah_entry_t[6236]` |
| `0x1C` | `uint32_t` | `word_dict_off` | Byte offset to `bqm_word_sprite_t[word_dict_count]` |
| `0x20` | `uint32_t` | `sprite_blob_off` | Byte offset to packed 1-bit word bitmap rows |
| `0x24` | `uint32_t` | `mushaf_pages_off`| Byte offset to pre-laid-out Mushaf subpage word placements |
| `0x28` | `uint32_t` | `text_blob_off` | Byte offset to pre-wrapped ASCII lines (`latin`, `translate`, `tafsir`) |
| `0x2C` | `char[20]` | `edition_tag` | Null-terminated summary (for example, `"Uthmani|ID-Kemenag"`) |

### 3.2 Index Tables

1. **Surah Table (`bqm_surah_entry_t`, 24 bytes × 114 = 2,736 bytes)**:
   ```c
   typedef struct __attribute__((packed)) {
       uint8_t  surah_number;       // 1..114
       uint16_t ayah_count;         // 3..286
       uint16_t first_global_ayah;  // 0..6235 index into ayah_table
       uint8_t  start_juz;          // 1..30
       char     name_latin[18];     // Null-terminated ASCII (e.g. "Al-Baqarah")
   } bqm_surah_entry_t;
   ```
2. **Ayah Table (`bqm_ayah_entry_t`, 24 bytes × 6,236 = 149,664 bytes)**:
   ```c
   typedef struct __attribute__((packed)) {
       uint8_t  juz;                // 1..30
       uint8_t  hizb_quarter;       // 1..240
       uint8_t  mushaf_subpages;    // Number of screens for Mushaf layer
       uint8_t  latin_subpages;     // Number of screens for Latin layer
       uint8_t  trans_subpages;     // Number of screens for Translation layer
       uint8_t  tafsir_subpages;    // Number of screens for Tafsir layer
       uint16_t reserved;
       uint32_t mushaf_off;         // Offset into mushaf_pages_off
       uint32_t latin_off;          // Offset into text_blob_off
       uint32_t trans_off;          // Offset into text_blob_off
       uint32_t tafsir_off;         // Offset into text_blob_off
   } bqm_ayah_entry_t;
   ```
3. **Word Sprite Dictionary (`bqm_word_sprite_t`, 8 bytes per unique word)**:
   ```c
   typedef struct __attribute__((packed)) {
       uint8_t  width;              // Tight cropped pixel width
       uint8_t  height;             // Tight cropped pixel height (1..48)
       int8_t   y_offset;           // Vertical offset from line top
       uint8_t  stride_bytes;       // (width + 7) / 8
       uint32_t bitmap_off;         // Offset inside sprite_blob_off
   } bqm_word_sprite_t;
   ```
4. **Mushaf Subpage Layout Record**:
   - Because the PWA receives the board's exact `display_width` and `display_height` via `0x19` (`GET_CONFIG`), it computes the `(x, y)` coordinates for each word on every `display_width x (display_height - 32)` Mushaf subpage at build time (`uint16_t` coordinates support all Kconfig display sizes `64..1024 px`):
   ```c
   typedef struct __attribute__((packed)) {
       uint16_t word_id;            // Index into bqm_word_sprite_t
       uint16_t x;                  // Left pixel coordinate (0..display_width-1, pre-aligned RTL)
       uint16_t y;                  // Top pixel coordinate (16..display_height-17)
   } bqm_placed_word_t;
   ```
   - Each Mushaf subpage is stored as `uint8_t word_count` followed by `bqm_placed_word_t[word_count]`. Firmware rendering requires a single `fread` of the subpage record and a direct 1-bit blit loop for each placed word.

## 4. Firmware Configuration & Build Integration

### 4.1 Kconfig & CMake Gating
- **`firmware/components/board_config/Kconfig`**:
  Add boolean option after `choice BOARD_PROFILE` (`line 15`):
  ```kconfig
  config BOARD_ALQURAN_ENABLE
      bool "Enable Optional Al-Quran Reader & .bqm Engine"
      default n
      help
          Compiles the Al-Quran top-level menu, .bqm binary reader, and
          independent NVS/RTC Tilawah state. Disabled on standard builds.
  ```
- **`firmware/components/quran_reader/CMakeLists.txt`**:
  Gate compilation of the entire `quran_reader` component at the CMake level ([firmware/RULES.md](./RULES.md) §2.3):
  ```cmake
  if(CONFIG_BOARD_ALQURAN_ENABLE)
      idf_component_register(
          SRCS "quran_reader.c"
          INCLUDE_DIRS "include"
          REQUIRES nvs_flash epaper board_config
      )
  else()
      idf_component_register()
  endif()
  ```
- **`firmware/CMakeLists.txt`**:
  Never pass Kconfig symbols as `-D` flags: `firmware/CMakeLists.txt` turns them into `BOARD_*` compiler macros, which do not set Kconfig, so `if(CONFIG_BOARD_ALQURAN_ENABLE)` and `#if CONFIG_BOARD_ALQURAN_ENABLE` would stay false. Add a Kconfig overlay `firmware/sdkconfig.alquran` containing `CONFIG_BOARD_ALQURAN_ENABLE=y`, selected with `-DSDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.alquran"`. No separate `BOARD_PROFILE` is added: the edition reuses `waveshare_154`.
- **`firmware/boards/boards.json`**:
  Add second build target sharing `boards/waveshare_154/board_def.h`:
  ```json
  {
    "id": "waveshare_154_alquran",
    "name": "Waveshare ESP32-S3-ePaper-1.54 (Al-Quran Edition)",
    "chip": "esp32s3",
    "flash_size": "8MB",
    "display": {
      "width": 200,
      "height": 200,
      "rotation": 0,
      "controller": "SSD1681"
    },
    "config_header": "boards/waveshare_154/board_def.h",
    "extra_idf_args": "-DCONFIG_BOARD_PROFILE_WAVESHARE_154=y -DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.alquran",
    "output_bin": "bacain_waveshare_154_alquran_factory.bin",
    "status": "supported"
  }
  ```
- **`.github/workflows/firmware_ci.yml`**:
  Use `.extra_idf_args // ("-DCONFIG_BOARD_PROFILE_" + (.id | ascii_upcase) + "=y")` in the `jq` matrix generator, and quote `EXTRA_IDF_ARGS` so the `;` in `SDKCONFIG_DEFAULTS` is not split by bash. Each matrix job starts from a clean checkout, so the overlay never leaks into the default build's `sdkconfig`.
- **Storage budget**:
  `package_firmware.py` sizes `storage` to `flash_size - 0x110000` (`3008K` on 4 MB, `7104K` on 8 MB). A full 30-Juz `quran.bqm` with all 4 layers must be measured in Stage 7; if it exceeds the 4 MB budget, the PWA range selector (`Juz 30 Only`, custom range) is the supported path for 4 MB boards, or the file is stored on MicroSD.

### 4.2 BLE Capability & Display Geometry Advertisement (`0x19`) & Quran State Sync (`0x20`, `0x21`)
- **`BLE_SYNC_OP_GET_CONFIG` (`0x19`, `firmware/components/ble_sync/ble_sync.c:1061-1073`)**:
  Extend `resp` from `10` bytes to `15` bytes:
  - `resp[0..9]`: Unchanged (`0x19`, status, `pwa_font_id`, `nav_hints`, `rotation`, `btn_invert`, `status_led`, `storage_target`, `sleep_timeout` LSB/MSB).
  - `resp[10]`: `capabilities` bitmask:
    ```c
    uint8_t caps = 0;
    #if CONFIG_BOARD_ALQURAN_ENABLE
    caps |= (1 << 0); // Bit 0: Al-Quran .bqm & NVS state support
    #endif
    resp[10] = caps;
    ```
  - `resp[11..12]`: `BOARD_DISPLAY_WIDTH` (`uint16_le`, LSB at `11`, MSB at `12`).
  - `resp[13..14]`: `BOARD_DISPLAY_HEIGHT` (`uint16_le`, LSB at `13`, MSB at `14`).
- **`BLE_SYNC_OP_GET_QURAN_STATE` (`0x20`, Read Device NVS Ground Truth)**:
  - Request: `[0x20]`
  - Response (40 bytes binary little-endian, `8` header + `8 x 4` bookmarks):
    - `resp[0]`: `0x20`
    - `resp[1]`: `status` (`0x00` = OK, `0x08` = Not supported)
    - `resp[2]`: `started` (`0` or `1`)
    - `resp[3]`: `active_surah` (`1..114`)
    - `resp[4..5]`: `active_ayah` (`uint16_le`, `1..286`)
    - `resp[6]`: `active_layer` (`0..3`)
    - `resp[7]`: `bookmark_count` (`0..8`)
    - `resp[8..39]`: `quran_bookmark_t[8]` (`8 × 4 bytes`: `{ uint8_t surah, uint16_le ayah, uint8_t juz }`)
- **`BLE_SYNC_OP_SET_QURAN_STATE` (`0x21`, Mutate & Persist to NVS Immediately)**:
  - Sub-command `0x01` (**Set Active Tilawah Cursor**):
    - Payload: `[0x21, 0x01, surah, ayah_lsb, ayah_msb, layer]` (6 bytes).
    - Action: Updates `s_rtc_quran_state` and commits immediately to NVS `"quran"`.
  - Sub-command `0x02` (**Set Bookmark Table**):
    - Payload: `[0x21, 0x02, count, ...bookmarks[count * 4]]` (up to 35 bytes).
    - Action: Replaces `bookmarks[]` in `s_rtc_quran_state`, commits immediately to NVS `"quran"`, and returns `[0x21, 0x00]`.

## 5. Independent State, Progress & Bookmark Architecture

### 5.1 Dedicated Component (`firmware/components/quran_reader/include/quran_reader.h`)
Isolated in its own ESP-IDF component (`firmware/components/quran_reader/`) and compiled only when `CONFIG_BOARD_ALQURAN_ENABLE` is active. Does not touch `reader_core` or `reading_state_t` (`book_library.h:49-55`).

```c
#define QURAN_MAX_BOOKMARKS 8

typedef enum {
    QURAN_LAYER_MUSHAF = 0,
    QURAN_LAYER_LATIN = 1,
    QURAN_LAYER_TRANSLATE = 2,
    QURAN_LAYER_TAFSIR = 3,
    QURAN_LAYER_COUNT = 4
} quran_layer_t;

typedef struct __attribute__((packed)) {
    uint8_t  surah;        // 1..114 (0 = empty slot)
    uint16_t ayah;         // 1..286
    uint8_t  juz;          // 1..30
} quran_bookmark_t;

typedef struct {
    bool             started;        // false on fresh device (suppresses 0% clutter)
    uint8_t          surah;          // Active Tilawah surah (1..114, default 1)
    uint16_t         ayah;           // Active Tilawah ayah (1..286, default 1)
    uint8_t          layer;          // quran_layer_t (default QURAN_LAYER_MUSHAF)
    uint8_t          subpage;        // 0..N-1 within active layer
    uint8_t          bookmark_count; // 0..QURAN_MAX_BOOKMARKS
    quran_bookmark_t bookmarks[QURAN_MAX_BOOKMARKS];
} quran_state_t;
```

- **Persistence**:
  - Fast wake retention: `static RTC_DATA_ATTR quran_state_t s_rtc_quran_state;` owned by `firmware/main/views/view_quran.c`.
  - Non-volatile persistence: Saved as a binary blob in NVS namespace `"quran"` key `"state"` in `app_enter_deep_sleep()` (`firmware/main/main.c`) and immediately on every cursor or bookmark mutation.

### 5.2 UI Views & 2-Button Navigation (`views/view_quran.*`)

All Quran screens live in `firmware/main/views/view_quran.h` / `view_quran.c` (`view_quran_render()`, `view_quran_handle_event()`, `view_quran_on_wake()`), following the existing `views/view_*.c` pattern. `main.c` only adds `case` lines to `dispatch_view_event()` and `dispatch_wake_view()`.

#### Top-Level Menu (`VIEW_MENU` in `firmware/main/views/view_menu.c`)
When `CONFIG_BOARD_ALQURAN_ENABLE` is active, `VIEW_MENU` has 8 items instead of 7:
- `0`: `Continue Reading` (opens `VIEW_READING` for standard `.txt` book)
- `1`: `Book Library` (opens `VIEW_BOOK_LIST` for `.txt` books)
- `2`: `Al-Quran` (checks `quran_reader_has_bqm()`; opens `VIEW_QURAN_MENU` or renders missing `.bqm` notice)
- `3`: `Font Size: [12px/16px]`
- `4`: `Sync Books`
- `5`: `Nav Hints`
- `6`: `Refresh Screen`
- `7`: `Power Off`

#### Al-Quran Sub-Menu (`VIEW_QURAN_MENU`)
If no `quran.bqm` exists on `/sdcard/books/quran.bqm` or `/spiflash/books/quran.bqm`, displays:
`No Al-Quran data (.bqm)` / `Sync via Web Companion` / `Hold ▲/▼ Back`.

When `quran.bqm` is present, displays 4 entries (`▲/▼ Move | 2x▲/▼ Select | Hold Back`):
1. **`Continue Tilawah`**:
   - If `started == true`: displays `Continue (2:255 • Juz 3)`.
   - If `started == false`: displays `Start Tilawah (1:1)` (no `0%` metric shown, per [AGENTS.md](../../AGENTS.md) §2.4).
2. **`Quick Presets & Juz`**:
   - Opens `VIEW_QURAN_JUMP` containing two sections:
     - **Sunnah Quick Presets (Top 5 rows)**:
       - `Al-Kahf (18:1)`
       - `Yasin (36:1)`
       - `Ar-Rahman (55:1)`
       - `Al-Waqiah (56:1)`
       - `Al-Mulk (67:1)`
     - **Juz Index (`Juz 1` .. `Juz 30`)**:
       - Selecting a Juz (`2x ▲/▼`) lists the Surahs inside that Juz, then opens the selected Surah at Ayah 1.
3. **`Bookmarks (N/8)`**:
   - Opens `VIEW_QURAN_BOOKMARKS`:
   - Lists saved bookmarks formatted as `1. Al-Baqarah 2:255 (Juz 3)`.
   - `2x ▼`: Jump to bookmark. `2x ▲`: Delete selected bookmark. `Hold ▲/▼`: Back to `VIEW_QURAN_MENU`.
4. **`Back to Main Menu`**:
   - Returns to `VIEW_MENU`.

#### Al-Quran Reading View (`VIEW_QURAN_READING`)
| Button Event | Action |
| :--- | :--- |
| **`1x ▼` (`BTN_ID_PWR` Click)** | Next subpage (`subpage++`). If at last subpage of active layer, advances to next ayah (`ayah++`, `subpage = 0`), or next Surah at ayah 1. Marks `started = true`. |
| **`1x ▲` (`BTN_ID_BOOT` Click)** | Previous subpage (`subpage--`), or previous ayah (`subpage = 0`). |
| **`2x ▲` (`BTN_ID_BOOT` Double-Click)** | Cycles active layer (`MUSHAF -> LATIN -> TRANSLATE -> TAFSIR -> MUSHAF`), skipping any layer absent in `bqm_header.layer_mask`. Keeps `(surah, ayah)` locked and resets `subpage = 0`. |
| **`2x ▼` (`BTN_ID_PWR` Double-Click)** | Toggles `(surah, ayah)` in `quran_state_t.bookmarks[]`, commits immediately to NVS `"quran"`, and renders `[★]` in header. |
| **`Hold ▲` or `Hold ▼` (Long Press)** | Saves state and exits to `VIEW_QURAN_MENU`. |

#### Screen Layout (`BOARD_DISPLAY_WIDTH x BOARD_DISPLAY_HEIGHT px`) in `VIEW_QURAN_READING`
- **Header (`y = 0..15`, inverted or underlined bar)**:
  - Left: `02:255 Al-Baqarah` (using `Font12`)
  - Right: Layer tag `[M]`, `[LAT]`, `[TRN]`, or `[TAF]` + Bookmark star `*` (if bookmarked) + Battery `%`.
- **Body (`y = 16..(BOARD_DISPLAY_HEIGHT - 17)`, `(BOARD_DISPLAY_HEIGHT - 32) px` height)**:
  - `QURAN_LAYER_MUSHAF`: Blits pre-placed 1-bit word sprites (`bqm_placed_word_t`) from `quran.bqm`.
  - `QURAN_LAYER_LATIN`, `TRANSLATE`, `TAFSIR`: Renders pre-wrapped ASCII lines sized to `BOARD_DISPLAY_WIDTH x (BOARD_DISPLAY_HEIGHT - 32)` using active `Font12` or `Font16`.
- **Footer (`y = (BOARD_DISPLAY_HEIGHT - 16)..(BOARD_DISPLAY_HEIGHT - 1)`)**:
  - When `reader_ui_get_show_nav_hints()` is true: `▲/▼ Page | 2x▲ Layer | 2x▼ Mark`
  - When `reader_ui_get_show_nav_hints()` is false: `Juz 3 • Hizb 5` on left, `1/2` (subpage indicator if `subpages > 1`) and khatam progress `%` (`global_ayah * 100 / 6236`, hidden when `0%`) on right.

## 6. PWA Companion Architecture (`web/`)

### 6.1 Capability & Screen Geometry Detection in `web/app.js`
- `web/index.html` remains untouched by Al-Quran scripts or static tags, ensuring zero payload overhead for standard book-reader users.
- In `applyDeviceConfigPayload(val)` (`web/app.js:1575-1636`):
  ```javascript
  const caps = val.byteLength > 10 ? val.getUint8(10) : 0;
  const rawW = val.byteLength >= 13 ? val.getUint16(11, true) : 200;
  const rawH = val.byteLength >= 15 ? val.getUint16(13, true) : 200;
  const rot  = val.getUint8(4);
  const screenW = (rot % 2 === 1) ? rawH : rawW;
  const screenH = (rot % 2 === 1) ? rawW : rawH;
  const alquranSupported = (caps & 0x01) !== 0;

  if (alquranSupported) {
    let qb = document.getElementById('quranBuilder');
    if (!qb) {
      await import('./components/quran-builder.js');
      qb = document.createElement('quran-builder');
      qb.id = 'quranBuilder';
      el.mainContent.appendChild(qb);
    }
    qb.setDisplayGeometry(screenW, screenH);
  } else {
    document.getElementById('quranBuilder')?.remove();
  }
  ```
- On disconnect (`updateConnectionUI`, `web/app.js:431`), remove `#quranBuilder` from the DOM (`document.getElementById('quranBuilder')?.remove()`).

### 6.2 Lazy-Loaded `<quran-builder>` Web Component (`web/components/quran-builder.js`)
Fetched and registered via `customElements.define('quran-builder', ...)` only when a board with `CAP_ALQURAN_SUPPORT` connects:

1. **Where Fonts & Quran Corpora Are Fetched From**:
   - **PWA Direct Fetch + Browser CacheStorage (`bacain-quran-v1`)**:
     - Fetched on-demand directly by the client PWA from CORS-enabled upstream CDNs/APIs and persisted in browser `CacheStorage` (`bacain-quran-v1`), ensuring instant offline access after initial fetch with zero repository or static-site bundle bloat:
       - Fonts:
         - `uthmani`: `https://verses.quran.foundation/fonts/quran/hafs/uthmanic_hafs/UthmanicHafs1Ver18.woff2` (King Fahd Complex Madinah Uthmani calligraphy)
         - `indopak`: `https://verses.quran.foundation/fonts/quran/hafs/nastaleeq/indopak/indopak-nastaleeq-waqf-lazim-v4.2.1.woff2` (IndoPak Naskh calligraphy)
       - Editions:
         - Uthmani text: `https://api.alquran.cloud/v1/quran/quran-uthmani`
         - IndoPak text: `https://cdn.jsdelivr.net/gh/fawazahmed0/quran-api@1/editions/ara-quranindopak.json` (fallback: `https://api.alquran.cloud/v1/quran/quran-indopak`)
         - Latin transliteration: `https://api.alquran.cloud/v1/quran/en.transliteration`
         - Translations: `https://api.alquran.cloud/v1/quran/id.indonesian` (ID), `https://api.alquran.cloud/v1/quran/en.sahih` (EN)
         - Tafsir: `https://api.alquran.cloud/v1/quran/id.jalalayn` (ID), `https://api.alquran.cloud/v1/quran/en.jalalayn` (EN)
   - Both `.woff2` fonts are loaded via `FontFace` and used only by the PWA's browser `<canvas>` to rasterize words into 1-bit monochrome sprites inside `quran.bqm`. The ESP32-S3 never parses `.ttf` or `.woff2` files.

2. **Mushaf Script & Content Configuration**:
   - **Mushaf Calligraphy Script Selector** (curated for 1-bit monochrome legibility; custom font upload and color-dependent Tajweed fonts are excluded):
     - `Madinah Uthmani Hafs (KFGQPC)` (Standard Saudi/Madinah Mushaf calligraphy)
     - `IndoPak 15-Line Naskh` (South/Southeast Asian Mushaf calligraphy with explicit vowel marks)
   - **Layer Checkboxes & Edition Selectors**:
     - `[x] Mushaf (1-Bit Word-Sprite Atlas)`
     - `[x] Latin Transliteration`
     - `[x] Translation` (`Indonesian - Kemenag RI` / `English - Saheeh International`)
     - `[x] Tafsir` (`Tafsir Ringkas Kemenag` / `Tafsir Al-Jalalayn`)
   - **Range Selector**:
     - `Full 30 Juz`
     - `Juz 30 ('Amma) Only` (~120 KB, fast BLE sync)
     - `Custom Juz / Surah Range`

3. **PWA Bookmark & Tilawah Manager (NVS Ground Truth via `0x20` / `0x21`)**:
   - On `<quran-builder>` mount, queries `0x20` (`BLE_SYNC_OP_GET_QURAN_STATE`) to load the device's authoritative NVS Tilawah cursor and 8 bookmark slots.
   - **Active Tilawah Control**:
     - Displays current reading position (`Surah`, `Ayah`, `Juz`, `Layer`) and allows jumping to any `Surah:Ayah` via dropdowns, committing immediately to device NVS via `[0x21, 0x01, ...]`.
   - **Bookmark List Manager (`0..8` Slots)**:
     - Lists all saved device bookmarks (`Surah Name`, `Surah:Ayah`, `Juz`).
     - Provides `Add Bookmark (Surah + Ayah picker)`, `Delete`, and `Move Up/Down` actions that push `[0x21, 0x02, ...]` to commit immediately to device NVS `"quran"`.

4. **Dynamic 1-Bit Preview Canvas (`screenW x screenH`)**:
   - Sizes the `<canvas>` `width` and `height` attributes dynamically to the connected firmware's reported screen geometry (`screenW x screenH` from `BOARD_DISPLAY_WIDTH`, `BOARD_DISPLAY_HEIGHT`, and active `rotation`).
   - Renders a live 1-bit pixel preview of the selected `Surah:Ayah` in the chosen Mushaf script (`Madinah Uthmani` or `IndoPak`) at exact target hardware resolution before building.

5. **Client-Side `.bqm` Compiler (`web/processors/bqm-builder.js`)**:
   - Loads the selected Mushaf `.woff2` font (`KFGQPC-Uthmanic-Hafs-v22.woff2` or `IndoPak-Naskh-15Line.woff2`) via browser `FontFace`.
   - Iterates through unique Quranic words, renders each word onto an `OffscreenCanvas` at `36 px`, applies 1-bit luminance thresholding, computes tight black-pixel bounds `(width, height, y_offset)`, and packs 1-bit rows into the sprite dictionary.
   - Uses the device's `screenW` and `screenH` (`bodyH = screenH - 32`) to compute RTL word placements `(x, y)` per subpage and pre-wrap `latin`, `translate`, and `tafsir` strings into columns matching `screenW`.
   - Writes `screenW` and `screenH` into `bqm_header.display_width` and `bqm_header.display_height`, emits `File([bqmBuffer], 'quran.bqm')`, and dispatches the existing `file-select` upload pipeline (`web/app.js:1149-1171`).
